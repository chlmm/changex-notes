# 调试

> 这是 VS IDE 区别于其他编辑器的核心价值。值得花时间掌握。

## 调试策略总览

```
你想调试什么？
├─ 程序崩溃 ──→ 先定位崩溃点，再逆推原因
├─ 逻辑错误（结果不对）──→ 在关键节点设断点，逐步验证
├─ 性能问题 ──→ 见 profiling-diagnostics.md
├─ 多线程问题 ──→ 线程窗口 + 条件断点
└─ 第三方库问题 ──→ 远程调试 / 符号文件配置
```

## 基础调试流程

### 启动调试

```
1. 设置断点 → 在感兴趣的行 切换断点
2. 开始调试
3. 程序停在断点处
4. 用 逐过程 / 逐语句 / 跳出 控制执行
5. 在监视窗口检查变量
6. 继续运行 (F5) 到下一个断点
```

### 逐过程 vs 逐语句

```
逐语句 ──→ 进入函数内部，看每一步
逐过程 ──→ 把函数调用当作一步，不进入内部
跳出   ──→ 当前函数剩余部分直接跑完，停在调用者
```

**选择策略**：

| 场景 | 操作 | 原因 |
|------|------|------|
| 当前行的函数可能有 bug | 逐语句 | 需要看内部 |
| 当前行的函数是可靠的库函数 | 逐过程 | 不需要看内部 |
| 已进入函数但发现不是问题所在 | 跳出 | 快速回到调用者 |
| 想直接跑到某一行 | 运行到光标 | 比设断点更快 |

## 断点类型

### 普通断点

最常用，程序执行到该行时暂停。

### 条件断点

**场景**：循环中只在特定条件下暂停，比如 `i == 42` 时。

**设置**：
1. 右键断点（红色圆点）→ 条件
2. 输入条件表达式（如 `i == 42`、`str == "error"`）
3. 选择条件类型：为 true 时 / 命中次数时

**命中次数断点**：适合"第 N 次循环时暂停"，条件中选"命中次数"，输入如 `5`（第 5 次命中时暂停）。

### 数据断点

**场景**：某个变量的值被意外修改，想知道是谁改的。

**设置**：
1. 调试 → 新建断点 → 新建数据断点
2. 输入要监视的地址表达式（如 `&myVar`）
3. 当该内存地址的值改变时，程序自动暂停

**注意**：
- 只能在调试过程中设置（程序已暂停时）
- 对栈变量可能不可靠（地址会变）
- 适合堆上的变量

### 函数断点

**场景**：想在某个函数的入口处暂停，但不知道函数在哪。

**设置**：
1. 调试 → 新建断点 → 在函数处中断
2. 输入函数名（如 `MyClass::OnProcess`）
3. 程序执行到该函数时自动暂停

**用途**：调试 C++ 虚函数调用、回调函数等难以定位的场景。

## 调试窗口

### 监视窗口 (Watch)

**用途**：持续监视变量和表达式的值。

**技巧**：
- 可以输入任意合法的 C++ 表达式
- 数组可以用 `arr,10` 的格式显示前 10 个元素
- 指针可以强制转换：`(MyStruct*)ptr`
- 格式化显示：`value,x`（十六进制）、`value,d`（十进制）

### 局部变量窗口 (Locals)

**用途**：自动显示当前作用域的所有局部变量。不需要手动添加。

### 即时窗口 (Immediate)

**用途**：调试时执行表达式或调用函数。

```
> ? myVar          // 查看变量值
> ? func(arg)      // 调用函数并查看返回值
> myVar = 42       // 修改变量值
```

### 调用堆栈窗口 (Call Stack)

**用途**：查看程序是怎么走到当前断点的。

**关键操作**：
- 双击某一帧 → 切换到该帧的上下文，查看当时的局部变量
- 右键 → 显示外部代码 → 看到完整的调用链（包括系统函数）

### 内存窗口 (Memory)

**用途**：查看原始内存内容，排查内存问题。

**使用**：
1. 打开内存窗口
2. 在地址栏输入变量地址（如 `&buf`、`0x00FF1234`）
3. 右键设置显示格式（1/2/4/8 字节整数，十六进制等）

### 自动窗口 (Autos)

**用途**：自动显示当前行和上一行中使用到的变量。比局部变量窗口更聚焦。

## 多线程调试

### 线程窗口

**打开**：调试 → 窗口 → 线程

**功能**：
- 查看所有线程的状态（运行/暂停/阻塞）
- 冻结/解冻线程（右键 → Freeze/Thaw）
- 切换当前线程上下文
- 按线程标志搜索

### 并行监视

**打开**：调试 → 窗口 → 并行监视

**用途**：同时在多个线程中监视同一个表达式的值，适合排查并发问题。

### 多线程调试策略

```
死锁？
├─ 线程窗口 → 查看哪些线程在等待
├─ 调用堆栈 → 看每个线程卡在哪
└─ 分析锁的获取顺序是否一致

数据竞争？
├─ 条件断点 → 在共享数据被修改时暂停
├─ 数据断点 → 监视共享变量的修改者
└─ 并行监视 → 同时查看各线程的状态
```

## Debug Visualizer (natvis)

**用途**：自定义复杂类型在调试器中的显示方式，让 Watch 窗口显示更友好的信息。

### 添加 natvis 文件

1. 项目中添加 `.natvis` 文件
2. 或放到全局目录：`%USERPROFILE%\Documents\Visual Studio 2022\Visualizers\`

### 示例：为自定义链表添加可视化

```xml
<?xml version="1.0" encoding="utf-8"?>
<AutoVisualizer xmlns="http://schemas.microsoft.com/vstudio/debugger/natvis/2010">
  <Type Name="MyLinkedList">
    <DisplayString>{{ size={m_size} }}</DisplayString>
    <Expand>
      <LinkedListItems>
        <Size>m_size</Size>
        <HeadPointer>m_head</HeadPointer>
        <NextPointer>next</NextPointer>
        <ValueNode>value</ValueNode>
      </LinkedListItems>
    </Expand>
  </Type>
</AutoVisualizer>
```

## 远程调试

**场景**：在另一台机器上调试程序（如服务器、嵌入式设备）。

### 配置步骤

1. 目标机器上运行 `Remote Debugger`（VS 安装目录下的 `msvsmon.exe`）
2. 本机 VS 中：调试 → 附加到进程
3. 传输选"远程（无身份验证）"或"远程（Windows 身份验证）"
4. 输入目标机器 IP
5. 选择要调试的进程 → 附加

**注意**：
- 目标机器上需要有对应的 PDB 符号文件
- 源代码版本必须匹配

## 符号文件 (PDB)

### PDB 的作用

PDB 文件包含调试信息：变量名、函数名、行号映射。没有 PDB 就无法设置断点、查看变量名。

### 符号加载配置

1. 工具 → 选项 → 调试 → 符号
2. 添加符号服务器路径（如微软公共符号服务器）
3. 添加本地符号缓存目录

### 符号加载问题排查

```
断点显示空心圆（无法命中）？
├─ PDB 没生成？
│  → 属性 → 链接器 → 调试 → 生成调试信息 → 是
├─ PDB 和 exe 不匹配？
│  → 重新生成（改了代码但 PDB 是旧的）
├─ PDB 加载被跳过？
│  → 模块窗口 → 右键模块 → 手动加载符号
└─ 优化导致代码被内联/消除？
   → 切换到 Debug 配置或禁用优化
```

## 调试技巧集

| 技巧 | 操作 | 场景 |
|------|------|------|
| 修改变量值 | 监视窗口中双击值列修改 | 想测试某个分支但不改代码 |
| 编辑并继续 | Debug 模式下直接改代码继续调试 | 小修改不想重启调试 |
| 设置下一语句 | 右键代码行 → 设置下一语句 | 想跳过/重试某段代码 |
| 拖动执行指针 | 黄色箭头直接拖到目标行 | 同上，更快 |
| 导出断点 | 断点窗口 → 导出 | 和团队共享断点配置 |
