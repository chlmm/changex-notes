# 重构

## 核心原则：C++ 重构的风险等级

C++ 的重构比 Java/C# 危险得多——头文件、链接、模板、宏都会让重构产生意外后果。

```
重构操作的安全等级
├─ 🟢 安全（编译器帮你检查）───→ 重命名、提取函数
├─ 🟡 需要验证（可能遗漏边界情况）───→ 移动定义、更改签名
└─ 🔴 高风险（容易引入隐蔽 bug）───→ 大规模 Include 重构、模板相关重构
```

**通用规则**：重构后必须编译 + 跑测试，不能只靠肉眼看。

## 重构工作流

### 重命名

**安全等级**：🟢

**操作**：光标放在符号上 → 重命名

**适用场景**：
- 变量、函数、类、命名空间
- 头文件中声明的符号（会同时修改声明和定义）

**注意**：
- 字符串中的同名文本不会被重命名（这是正确行为）
- 如果符号在宏中使用，可能不会重命名宏内部的引用
- 重命名类时不会自动重命名文件（需要手动处理）

### 提取函数

**安全等级**：🟢

**操作**：选中代码块 → 提取函数

**适用场景**：
- 一个函数太长，拆分成小函数
- 一段逻辑在多处重复

**注意**：
- 选中的代码块需要是连续的语句
- 局部变量会自动变成参数或返回值
- 提取后检查生成的函数签名是否合理

### 提取变量

**安全等级**：🟢

**操作**：选中表达式 → 提取变量

**适用场景**：
- 复杂表达式拆成有名字的变量，提升可读性
- 同一个表达式出现多次

### 移动定义

**安全等级**：🟡

**操作**：光标放在函数定义上 → 移动定义

**两种方向**：

| 方向 | 场景 | 风险 |
|------|------|------|
| 从 .cpp 移到 .h（内联） | 小函数、模板函数 | 增加头文件依赖，可能影响编译时间 |
| 从 .h 移到 .cpp | 大函数、只在本编译单元使用 | 需要确保头文件有正确声明 |

**注意**：
- 移动后检查 include 是否完整
- 模板函数通常不能移到 .cpp（除非显式实例化）

### 更改签名

**安全等级**：🟡

**操作**：光标放在函数上 → 更改签名

**可以修改**：
- 参数顺序
- 参数类型
- 参数名称
- 添加/删除参数

**注意**：
- 所有调用点会被自动更新，但默认参数的推导可能不符合预期
- 虚函数的签名修改会影响所有子类，子类可能不会被自动更新
- 回调函数/函数指针的签名修改需要手动处理

## Include 管理

### Include 整理策略

```
头文件中的 #include
├─ 这个头文件被其他头文件间接包含了？
│  ├─ 是，且不是本头文件直接需要的 ──→ 删除（不要依赖传递依赖）
│  └─ 是，且本头文件直接需要 ──→ 保留
└─ 不确定？───→ 删除后编译，如果报错就加回来
```

### Include 排序建议

```cpp
// 1. 对应的头文件（如 foo.cpp 中的 foo.h）
#include "foo.h"

// 2. 空行

// 3. C 系统头文件
#include <cstdio>
#include <cstring>

// 4. C++ 标准库
#include <string>
#include <vector>

// 5. 空行

// 6. 第三方库
#include <fmt/format.h>

// 7. 项目内头文件
#include "mylib/utils.h"
```

### 前向声明 vs #include

```
什么时候用前向声明？
├─ 只用到指针/引用类型 ──→ 前向声明
├─ 只在函数参数/返回值中出现 ──→ 前向声明
├─ 需要访问类成员 ──→ 必须 #include
├─ 需要调用类方法 ──→ 必须 #include
├─ 继承某个类 ──→ 必须 #include
└─ 模板参数需要完整类型 ──→ 必须 #include
```

## 策略树：我想重构 X

### 提取重复代码

```
发现重复代码
├─ 同一函数内重复 ──→ 提取变量 / 提取函数
├─ 不同函数间重复 ──→ 提取函数 到公共模块
├─ 不同类之间重复 ──→ 提取到工具类/基类
└─ 只是相似但不完全相同 ──→ 提取函数 + 参数化差异部分
```

### 拆分大类

```
一个类职责太多
├─ 识别独立的职责边界
├─ 提取一组相关成员到新类
├─ 原类持有新类的指针/引用
├─ 逐步迁移调用方
└─ 每一步都编译测试
```

### 简化复杂条件

```
嵌套 if 太深
├─ 提取条件判断为有名字的函数（提取函数）
├─ 卫语句（提前 return）减少嵌套
├─ 合并条件（逻辑运算符组合）
└─ 策略模式替换大 switch
```

## 重构检查清单

每次重构后按此清单验证：

- [ ] 编译通过（零错误零警告）
- [ ] 测试通过
- [ ] 头文件 include 正确（不多不少）
- [ ] 没有引入循环依赖
- [ ] 代码格式化
- [ ] Git 提交粒度合理（一次重构一个提交）

## 常见问题

### 问题：重命名后编译报错

**原因**：VS 的重命名没有覆盖到所有引用。

**解决**：
1. 查找引用 手动确认是否有遗漏
2. 全局搜索 旧名称做最终验证

### 问题：提取函数后链接失败

**原因**：提取的函数声明和定义不一致，或头文件中缺少声明。

**解决**：检查 .h 中是否有对应声明，声明和定义的签名是否完全一致。
