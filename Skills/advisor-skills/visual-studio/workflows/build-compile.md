# 构建与编译

## Build 配置决策树

```
你要构建什么？
├─ 整个解决方案 ──→ 生成解决方案
├─ 只编译当前项目 ──→ 生成当前项目
├─ 只检查当前文件语法 ──→ 编译当前文件（不链接）
└─ 构建卡住了 ──→ 取消生成
```

## 构建工作流

### 日常开发循环

```
1. 写代码
2. 编译当前文件 → 快速验证语法
3. 有错？ → 错误列表 定位修复
4. 没错？ → 生成解决方案 → 完整构建
5. 通过？ → 开始调试
```

### 切换 Build 配置

```
开发调试阶段 → Debug（含调试信息，无优化）
性能测试阶段 → Release（全优化，无调试信息）
```

**关键区别**：

| | Debug | Release |
|---|-------|---------|
| 优化 | 禁用 (`/Od`) | 启用 (`/O2`) |
| 调试信息 | 有 (`/Zi`) | 可选 |
| 运行库 | Debug CRT (`/MDd`) | Release CRT (`/MD`) |
| 断言 | 启用 | 禁用 |
| 行为 | 可能有未初始化内存清零 | 内存内容不确定 |

## 常用编译器选项速查

### C++ 标准版本

| 选项 | 值 | 说明 |
|------|---|------|
| C++ 语言标准 | `/std:c++14` | 默认 |
| | `/std:c++17` | 常用现代标准 |
| | `/std:c++20` | 最新特性 |
| | `/std:c++latest` | 实验性最新 |

**配置路径**：属性 → C/C++ → 语言 → C++ 语言标准

### 警告等级

| 选项 | 值 | 建议 |
|------|---|------|
| 警告等级 | `/W1` | 太少 |
| | `/W2` | 默认 |
| | `/W3` | 推荐 |
| | `/W4` | **强烈推荐**，几乎所有警告都开 |
| 视警告为错误 | `/WX` | CI/CD 中推荐，本地可不开 |

**配置路径**：属性 → C/C++ → 常规 → 警告等级

### 运行库

| 选项 | 值 | 说明 |
|------|---|------|
| 多线程调试 DLL | `/MDd` | Debug 默认，链接 Debug CRT DLL |
| 多线程 DLL | `/MD` | Release 默认，链接 Release CRT DLL |
| 多线程调试 | `/MTd` | 静态链接 Debug CRT |
| 多线程 | `/MT` | 静态链接 Release CRT，部署时不需 CRT DLL |

**配置路径**：属性 → C/C++ → 代码生成 → 运行库

**注意**：所有链接在一起的 lib 和你的项目必须使用相同的运行库选项，否则会报链接错误。

## 错误排查策略树

### 编译错误

```
编译报错
├─ 语法错误 (C2xxx)
│  → 看行号定位，读错误信息
│  → 常见原因：缺分号、括号不匹配、拼写错误
├─ 找不到头文件 (C1083)
│  → 参见 project-setup.md "找不到头文件" 排查路径
├─ 类型不匹配 (C2440, C2664)
│  → 检查隐式转换、宽窄字符、指针类型
└─ 重定义 (C2011, LNK2005)
   → 检查头文件是否缺少 include guard 或 #pragma once
```

### 链接错误

```
链接报错
├─ LNK2019: unresolved external symbol
│  → 参见 project-setup.md "链接错误 LNK2019" 排查路径
├─ LNK2005: already defined
│  → 头文件中写了定义而非声明（模板/inline 除外）
│  → 同一 .cpp 被多次包含
├─ LNK1104: cannot open file
│  → .lib 文件路径不对或被占用
│  → 32/64 位不匹配
└─ LNK2001: unresolved external symbol（但函数确实存在）
   → 调用约定不一致（__cdecl vs __stdcall）
   → C++ name mangling 问题，需要 extern "C"
```

### 增量构建问题

```
改了代码但构建说"已是最新"？
├─ 手动触发 → 重新生成
├─ 可能是时间戳问题
│  → 清理 → 生成解决方案
└─ .obj 缓存损坏
   → 清理 → 生成解决方案
```

## 编译优化技巧

### 加快编译速度

| 方法 | 效果 | 操作 |
|------|------|------|
| 预编译头 (PCH) | ⭐⭐⭐ | 属性 → C/C++ → 预编译头 → 创建/使用 |
| 多进程编译 | ⭐⭐ | 属性 → C/C++ → 常规 → 多进程编译 → 是 (`/MP`) |
| 前向声明替代 include | ⭐⭐ | 代码层面优化 |
| 最小化头文件包含 | ⭐⭐ | 用 `#pragma once` + 减少传递依赖 |
| 增量链接 | ⭐ | 属性 → 链接器 → 常规 → 启用增量链接 |

### 预编译头配置

```
1. 创建 pch.h / pch.cpp
2. pch.cpp 属性 → C/C++ → 预编译头 → 创建 (/Yc)
3. 其他 .cpp 属性 → C/C++ → 预编译头 → 使用 (/Yu)
4. 在 pch.h 中 include 不常变动的头文件（如 <vector>, <string>, <Windows.h>）
```

## 常见问题

### 问题：Debug 能编译但 Release 报错

**常见原因**：
- Release 下启用了优化，暴露了未定义行为
- 运行库不匹配（Debug 用 `/MDd`，但链接了 Release 的 lib）
- 条件编译 `#ifdef _DEBUG` 导致代码路径不同

### 问题：改了头文件但没重新编译依赖的 .cpp

**原因**：增量构建依赖关系出错。

**解决**：重新生成，或检查头文件的 include 关系是否正确。
