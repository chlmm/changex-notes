# 重构

## Qt Creator 重构能力总览

Qt Creator 的重构能力比 VS 弱，但有 Qt 特有的重构操作。

```
重构操作安全等级
├── 🟢 安全（编译器帮你检查）
│   ├── 重命名
│   ├── 提取函数
│   ├── 提取变量
│   └── 添加 getter/setter
├── 🟡 需要验证
│   ├── 移动定义
│   ├── 更改签名
│   └── 信号槽连接重构
└── 🔴 高风险
    ├── 大规模 Include 重构
    └── 模板相关重构
```

## 基础重构操作

### 重命名

**操作**：光标放在符号上 → 右键 → Refactor → Rename

或使用快速修复 → 选择 Rename

**适用**：
- 变量、函数、类、命名空间
- Qt 信号和槽的名称

**注意**：
- Qt Creator 的重命名有时不如 VS 全面，可能遗漏某些引用
- 重命名信号时需要手动更新对应的 connect 语句
- 建议重命名后用查找引用 验证完整性

### 提取函数

**操作**：选中代码块 → 右键 → Refactor → Extract Function

**注意**：
- 选中的代码需要是连续语句
- 局部变量自动变成参数或返回值
- 提取后检查生成的函数签名

### 提取变量

**操作**：选中表达式 → 右键 → Refactor → Extract Variable

### 添加 getter/setter

**操作**：光标放在成员变量上 → 右键 → Refactor → Generate Getter/Setter

Qt Creator 会自动生成：
- getter 函数声明和定义
- setter 函数声明和定义
- 可选：生成信号（属性变化通知）

## Qt 特有重构

### 信号槽连接

**操作**：光标放在信号声明上 → 右键 → Refactor → Connect Signal/Slot

Qt Creator 帮你：
1. 在接收者类中生成槽函数声明
2. 在 .cpp 中生成槽函数骨架
3. 在合适位置生成 connect 语句

### 添加 Q_PROPERTY

**操作**：右键 → Refactor → Generate Q_PROPERTY

自动生成属性声明，包括 READ/WRITE/NOTIFY。

### 添加 Q_DECLARE_METATYPE

**操作**：对自定义类型右键 → Refactor → Add Q_DECLARE_METATYPE

让自定义类型可以在 QVariant 和信号槽中使用。

## Include 管理

### 添加前向声明 / #include

**操作**：光标放在未识别的类型上 → 快速修复

Qt Creator 会提示：
- 添加 `#include`（需要完整类型）
- 添加前向声明（只需指针/引用）

### 删除未使用的 #include

Qt Creator 不会自动删除未使用的 include，需要手动检查。

**策略**：

```
整理 include
1. 删除可疑的 #include
2. 构建项目
3. 如果编译通过 → 确实不需要
4. 如果编译失败 → 加回来
5. 每次处理一个，不要批量删除
```

## 策略树：我想重构 X

### 提取重复代码

```
发现重复代码
├── 同一函数内重复 ──→ 提取变量 / 提取函数
├── 不同函数间重复 ──→ 提取函数到公共模块
├── 不同类之间重复 ──→ 提取到基类或工具类
└── 只是相似但不完全相同 ──→ 提取函数 + 参数化差异部分
```

### 拆分大类

```
一个 QObject 子类太大
1. 识别独立的职责边界
2. 将一部分信号/槽/属性移到新类
3. 原类持有新类的指针
4. 迁移 connect 语句
5. 每步编译测试
```

### 重构信号槽

```
信号槽连接需要改
├── 只改槽实现？→ 直接修改槽函数体（安全）
├── 改信号/槽签名？→ 重命名 + 手动更新所有 connect
├── 合并多个信号？→ 在中间层统一转发
└── 拆分信号？→ 确保所有连接方都更新
```

## 重构检查清单

- [ ] 编译通过
- [ ] 运行测试（如有）
- [ ] 查找引用 确认无遗漏
- [ ] Qt 项目额外检查：
  - [ ] MOC 相关文件是否重新生成？
  - [ ] 信号槽连接是否都更新了？
  - [ ] .ui 文件中的信号槽连接是否需要更新？
  - [ ] Q_PROPERTY 的 READ/WRITE/NOTIFY 是否一致？
- [ ] Git 提交粒度合理

## Qt Creator vs VS 重构能力对比

| 操作 | VS | Qt Creator |
|------|----|-----------|
| 重命名 | ✅ 全面 | ✅ 偶尔遗漏 |
| 提取函数 | ✅ | ✅ |
| 提取变量 | ✅ | ✅ |
| 内联变量 | ✅ | ❌ |
| 移动定义 | ✅ | ✅ |
| 更改签名 | ✅ | ⚠️ 有限 |
| 生成 getter/setter | ❌ | ✅ Qt 特有 |
| 信号槽连接 | ❌ | ✅ Qt 特有 |
| 添加 Q_PROPERTY | ❌ | ✅ Qt 特有 |

**结论**：Qt Creator 在 Qt 特有重构上更强，在通用重构上比 VS 弱。复杂的通用重构建议用 VS 或 ReSharper C++。

## 常见问题

### 问题：重命名后部分引用没更新

**解决**：
1. 全局搜索 旧名称
2. 手动确认每个搜索结果
3. 更新遗漏的引用

### 问题：提取函数后 MOC 报错

**原因**：提取的函数涉及 Q_OBJECT 宏或信号槽。

**解决**：确保提取后的代码仍在同一个类中，不要跨类提取含信号槽调用的代码。
